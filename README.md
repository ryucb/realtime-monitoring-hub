# Realtime Monitoring Hub

Modbus 장비와 공공 API를 **병렬 폴링**으로 수집하고, Kafka와 WebSocket으로 화면·알림·저장에 실시간으로 나누는 개인 프로젝트입니다.

## 왜 만드나

이전 회사에서 산업용 장비 모니터링 플랫폼을 혼자 개발했습니다. 장비가 15대를 넘으면 화면 반영이 약 10초 늦어졌고, 원인은 **단일 스레드 순차 폴링**이었습니다. 당시에는 일정 때문에 Kafka + WebSocket으로 화면 지연(약 10초 → 2~3초)만 먼저 줄였고, 근본 해결책인 병렬 폴링 전환은 하지 못했습니다.

이 프로젝트에서는 그 개선을 직접 끝까지 구현하고 측정합니다. 그리고 같은 구조로 출퇴근에 쓰는 실시간 알림(버스 도착·미세먼지·날씨)까지 만듭니다.

## 목표

- 가상 Modbus 장비 1~50대에서 단일 스레드 vs 병렬 폴링의 수집 주기와 화면 반영 지연을 숫자로 비교
- 장비와 공공 API를 하나의 `DataSource` 인터페이스로 추상화
- Kafka → WebSocket(STOMP) → Vue 실시간 대시보드
- 알림 규칙(조건·시간대·중복 방지) → 텔레그램 봇
- 실제 장비 없이 PC 한 대(Docker Compose)로 전 과정 진행

## 아키텍처

```
[가상 Modbus 장비] ─┐
[공공 API]        ─┼─▶ [병렬 수집기] ─▶ [Kafka] ─┬─▶ WebSocket ─▶ Vue 대시보드
[온습도 센서(선택)] ─┘   소스별 가상 스레드           ├─▶ 알림 규칙 ─▶ 텔레그램 봇
                        타임아웃·장애 격리            └─▶ 저장 컨슈머 ─▶ MySQL
```

## 기술 스택

Java 21, Spring Boot 4.1, Kafka, WebSocket(STOMP), Vue, MySQL, Docker Compose

## 실행 방법

Java 21이 필요합니다. Gradle은 `gradlew`가 처음 실행할 때 자동으로 내려받습니다(Windows는 `gradlew.bat`).

터미널 두 개를 엽니다.

```bash
# 터미널 1: 가상 Modbus 장비 15대 띄우기 (포트 15020~15034, 응답 지연 100ms)
./gradlew simulator --args="15 15020 100"

# 터미널 2: 수집 서버(Spring Boot) 실행 → 1초 간격으로 장비 15대를 폴링
./gradlew bootRun
```

수집 서버가 뜨면 브라우저에서 확인합니다.

- http://localhost:8080/api/readings : 장비별 최신 값
- http://localhost:8080/api/status : 마지막 한 바퀴의 폴링 방식, 성공 수, 소요 시간
- http://localhost:8080/actuator/health : 서버 상태

장비 수, 포트, 폴링 주기는 `src/main/resources/application.yml`에서 바꿉니다.

```bash
# 테스트
./gradlew test

# 장비 수별 폴링 한 바퀴 시간 측정 (응답 지연 100ms, 5바퀴, 장비 1·5·15·30·50대)
./gradlew benchmark --args="100 5 1,5,15,30,50"

# Kafka, MySQL (3주차부터 사용)
cp .env.example .env
docker compose up -d
```

## 측정 결과

### 1주차: 단일 스레드 순차 폴링 (승일 구조 재현)

장비 응답 지연 100ms, 3바퀴 평균. 원본 값은 [results/](./results) 폴더에 있습니다.

| 장비 수 | 한 바퀴 평균 |
| --- | --- |
| 1대 | 101ms |
| 5대 | 506ms |
| 15대 | 1,519ms |
| 30대 | 3,028ms |
| 50대 | 5,044ms |

한 바퀴 시간이 **장비 수 × 장비 응답 시간**으로 그대로 늘어납니다. 스레드 하나가 한 장비의 응답을 기다리는 동안 나머지 장비는 아무것도 하지 못하기 때문입니다. 실제 현장 장비는 RS-485 직렬 통신과 무선 변환기를 거치면서 응답이 이보다 느려 지연이 더 커집니다. 2주차에 병렬 폴링으로 바꾼 뒤 같은 조건에서 비교합니다.
