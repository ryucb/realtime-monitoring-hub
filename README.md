# Realtime Monitoring Hub

Modbus 장비와 공공 API를 **병렬 폴링**으로 수집하고, Kafka와 WebSocket으로 화면·알림·저장에 실시간으로 나누는 개인 프로젝트입니다.

## 왜 만드나

이전 회사에서 산업용 장비 모니터링 플랫폼을 혼자 개발했습니다. 장비가 15대를 넘으면 화면 반영이 약 10초 늦어졌고, 원인은 **단일 스레드 순차 폴링**이었습니다. 당시에는 일정 때문에 Kafka + WebSocket으로 화면 지연(약 10초 → 2~3초)만 먼저 줄였고, 근본 해결책인 병렬 폴링 전환은 하지 못했습니다.

이 프로젝트에서는 그 개선을 직접 끝까지 구현하고 측정합니다. 그리고 같은 구조로 출퇴근에 쓰는 실시간 알림(버스 도착·미세먼지·날씨)까지 만듭니다.

## 목표

- 가상 Modbus 장비 1~50대에서 단일 스레드 vs 병렬 폴링의 수집 주기와 화면 반영 지연을 숫자로 비교
- 장비와 공공 API를 하나의 `DataSource` 인터페이스로 추상화
- Kafka → WebSocket(STOMP) → Vue 실시간 대시보드
- 알림 규칙(조건·시간대·중복 방지) → 텔레그램 봇
- 실제 장비 없이 PC 한 대(Docker Compose)로 전 과정 진행

## 아키텍처

```
[가상 Modbus 장비] ─┐
[공공 API]        ─┼─▶ [병렬 수집기] ─▶ [Kafka] ─┬─▶ WebSocket ─▶ Vue 대시보드
[온습도 센서(선택)] ─┘   소스별 가상 스레드           ├─▶ 알림 규칙 ─▶ 텔레그램 봇
                        타임아웃·장애 격리            └─▶ 저장 컨슈머 ─▶ MySQL
```

## 기술 스택

Java 21, Spring Boot, Kafka, WebSocket(STOMP), Vue, MySQL, Docker Compose

## 진행 계획 (6주)

| 주차 | 내용 | 상태 |
| --- | --- | --- |
| 1주 | Docker 환경, Modbus 시뮬레이터, 단일 스레드 폴링 재현·측정 | ⏳ |
| 2주 | 병렬 폴링 전환(스레드 풀 / 가상 스레드), 장애 격리, 벤치마크 | ⏳ |
| 3주 | Kafka 토픽 설계, WebSocket 푸시, Vue 대시보드 | ⏳ |
| 4주 | 공공 API 소스, 알림 규칙, 텔레그램 봇 | ⏳ |
| 5주 | 상시 운영 배포, 선택 기능 | ⏳ |
| 6주 | 문서·벤치마크 그래프·회고 | ⏳ |

## 실행 방법

```bash
cp .env.example .env
docker compose up -d   # Kafka, MySQL
```

## 측정 결과

1~2주차 측정 후 채웁니다.
